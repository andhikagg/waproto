waproto

The latest WhatsApp protobuf definitions, built automatically for Baileys and installed with two commands.

Definisi protobuf WhatsApp terbaru, dibuild otomatis untuk Baileys dan dipasang dengan dua perintah.

Built from wppconnect-team/wa-proto every time upstream changes. Not affiliated with or endorsed by WhatsApp or Meta.

Dibuild dari wppconnect-team/wa-proto setiap kali upstream berubah. Tidak ada hubungannya dengan WhatsApp maupun Meta.

[01]Quick startMulai cepat

Run both commands in your Baileys project root, in this order. Requires Node.js 18 or newer.

Jalankan kedua perintah ini di root proyek Baileys-mu, berurutan. Butuh Node.js 18 atau lebih baru.

[1]Update protobufjs (required)Update protobufjs (wajib)
curl -fsSL https://andhikagg.github.io/waproto/fix.js | TARGET="baileys" node -
[2]Patch WAProtoPatch WAProto
curl -fsSL https://andhikagg.github.io/waproto/patch.js | TARGET="baileys" node -

TARGET is the package folder name inside node_modules, for example:

TARGET adalah nama folder paket di dalam node_modules, contohnya:

TARGET="baileys"
TARGET="@whiskeysockets/baileys"

Pairing again is usually not required. If you get connection or decryption errors after patching, delete your Baileys auth/session folder and pair again (scan the QR code).

Biasanya kamu tidak perlu pairing ulang. Tapi kalau setelah patch muncul error koneksi atau dekripsi, hapus folder auth/session Baileys lalu pairing lagi (scan QR code).

These commands run a script from this repository with your permissions. Read them first, or use a URL pinned to a commit hash. See Notes.

Perintah ini menjalankan skrip dari repo ini dengan izinmu. Baca dulu isinya, atau pakai URL yang dikunci ke hash commit. Lihat Catatan.

[02]How it worksCara kerja

  1. A GitHub Actions workflow checks the upstream repo every hour.
  2. If there is a new upstream commit, it runs update.sh on the WAProto.proto from exactly that commit:
    • downloads the file and checks that it really is a .proto
    • replaces proto3-illegal required with optional (field declarations only)
    • compiles it with pbjs (ES module output) and makes typings with pbts
    • renames the waproto namespace to proto in both index.js and index.d.ts, and applies known Baileys quirks
    • validates the syntax and zips the output
  3. The result is committed to WAProto/ and the zip is uploaded as a workflow artifact.
  4. On your machine, two small scripts install everything into node_modules: fix.js updates the protobufjs runtime inside the Baileys module, and patch.js installs the built WAProto files.
  1. Workflow GitHub Actions mengecek repo upstream setiap jam.
  2. Kalau ada commit baru, workflow menjalankan update.sh untuk WAProto.proto dari commit itu:
    • mengunduh file dan memastikan isinya memang .proto
    • mengganti required (tidak valid di proto3) jadi optional, hanya di deklarasi field
    • mengompilasinya dengan pbjs (output ES module) dan membuat typings dengan pbts
    • mengganti namespace waproto jadi proto di index.js dan index.d.ts, plus penyesuaian khusus Baileys
    • mengecek sintaks dan membuat zip dari hasilnya
  3. Hasilnya di-commit ke WAProto/, dan zip-nya diunggah sebagai artifact workflow.
  4. Di komputermu, dua skrip kecil memasang semuanya ke node_modules: fix.js memperbarui runtime protobufjs di dalam modul Baileys, dan patch.js memasang file WAProto hasil build.

[03]ReferenceReferensi

fix.js — use the latest protobufjspakai protobufjs terbaru

The generated index.js is compiled with a recent protobufjs-cli and imports protobufjs/minimal. The runtime that Baileys resolves must be recent too. An old runtime causes missing methods, decode failures, or import errors, for example reader.size is not a function.

index.js hasil build dikompilasi dengan protobufjs-cli yang baru dan mengimpor protobufjs/minimal. Runtime yang dipakai Baileys juga harus baru. Runtime lama menyebabkan method tidak ketemu, gagal decode, atau error import, misalnya reader.size is not a function.

  1. Leaves package-lock.json alone (set RESET_LOCK=1 to delete it).
  2. Rewrites node_modules/<TARGET>/package.json so protobufjs uses the wanted version. The original is saved once as package.json.bak.
  3. Runs npm install protobufjs@<version> in the project root.
  4. Copies node_modules/protobufjs into node_modules/<TARGET>/node_modules/protobufjs (skipped if it is already the same version).
  5. Replaces latest in package.json with a real range such as ^8.8.1, so npm ls does not report it as invalid.
  1. Tidak menyentuh package-lock.json (kalau mau dihapus, pakai RESET_LOCK=1).
  2. Mengubah node_modules/<TARGET>/package.json supaya protobufjs memakai versi yang kamu mau. File aslinya disimpan sekali sebagai package.json.bak.
  3. Menjalankan npm install protobufjs@<versi> di root proyek.
  4. Menyalin node_modules/protobufjs ke node_modules/<TARGET>/node_modules/protobufjs (dilewati kalau sudah versi yang sama).
  5. Mengganti latest di package.json dengan rentang versi asli seperti ^8.8.1, supaya npm ls tidak menandainya invalid.
TARGETbaileys

Package name in node_modules. Run from the project root.

Nama paket di node_modules. Jalankan dari root proyek.

SKIP_INSTALL

Set to 1 to skip npm install (use if protobufjs is already installed in the project root).

Isi 1 untuk melewati npm install (kalau protobufjs sudah terpasang di root proyek).

PROTOBUFJS_VERSIONlatest

protobufjs version or range, for example ^7. Avoids surprises from new major releases.

Versi atau rentang versi protobufjs, misalnya ^7. Supaya tidak kaget kalau ada rilis mayor baru.

RESET_LOCK

Set to 1 to delete package-lock.json in the project root.

Isi 1 untuk menghapus package-lock.json di root proyek.

Check which version is actually resolved:

Untuk cek versi yang benar-benar terpakai:

npm ls protobufjs
node -e "console.log(require('protobufjs/package.json').version)"

npm install or npm ci rebuilds node_modules and removes the copied module. Run both scripts again afterwards, or add them to the postinstall script of your own package.json. SKIP_INSTALL=1 keeps the script from calling npm install inside an install. Make sure protobufjs is listed in your own dependencies. Both scripts are safe to run repeatedly.

Setiap kali kamu menjalankan npm install atau npm ci, node_modules dibangun ulang dan modul hasil salinan ikut hilang. Jalankan kedua skrip lagi setelahnya, atau masukkan ke postinstall di package.json-mu. SKIP_INSTALL=1 mencegah skrip memanggil npm install di tengah proses install. Pastikan protobufjs sudah ada di dependensi proyekmu. Kedua skrip aman dijalankan berkali-kali.

{
  "scripts": {
    "postinstall": "curl -fsSL https://andhikagg.github.io/waproto/fix.js | TARGET=baileys SKIP_INSTALL=1 node - && curl -fsSL https://andhikagg.github.io/waproto/patch.js | TARGET=baileys node -"
  }
}

patch.js — optionsopsi

TARGETbaileys

Package name in node_modules (searched upward from the current directory).

Nama paket di node_modules (dicari naik ke folder induk dari folder saat ini).

SOURCE…/andhikagg/waproto/main/WAProto

Base URL that serves index.js, index.d.ts and WAProto.proto. Must be https://.

URL dasar tempat index.js, index.d.ts, dan WAProto.proto diambil. Harus https://.

DRY_RUN

Set to 1 to download and validate only, without writing anything.

Isi 1 untuk hanya mengunduh dan memvalidasi, tanpa menulis apa pun.

FORCE

Set to 1 to install even if the protobufjs runtime check fails.

Isi 1 untuk tetap memasang walau cek runtime protobufjs gagal.

  • Downloads everything into memory first. Empty or tiny files are rejected and index.js is syntax-checked before node_modules is touched.
  • Checks that the protobufjs runtime has what the new index.js needs (for example Reader.size()) and stops before writing anything if it does not.
  • If your protobufjs has no exports map, adds .js to the protobufjs/minimal import so Node ESM can resolve it.
  • If index.d.ts still uses the waproto namespace, renames it to proto.
  • Only writes files that changed, backs each one up as *.bak, writes through a temporary file, and rolls back automatically if a write fails.
  • Warns if the module format differs (ESM vs CommonJS) between the installed and new file.
  • Mengunduh semuanya ke memori dulu. File kosong atau terlalu kecil ditolak dan sintaks index.js dicek sebelum node_modules disentuh.
  • Mengecek apakah runtime protobufjs punya yang dibutuhkan index.js baru (misalnya Reader.size()), dan berhenti sebelum menulis apa pun kalau tidak.
  • Kalau protobufjs-mu tidak punya exports map, menambahkan .js di import protobufjs/minimal supaya bisa dibaca Node ESM.
  • Kalau index.d.ts masih memakai namespace waproto, otomatis diganti jadi proto.
  • Hanya menulis file yang berubah, mencadangkan tiap file sebagai *.bak, menulis lewat file sementara, dan otomatis rollback kalau ada penulisan yang gagal.
  • Memberi peringatan kalau format modul (ESM vs CommonJS) file lama dan baru berbeda.

Set up the workflow and build manuallySiapkan workflow dan build manual

  1. Put update.sh in the repo root and the workflow at .github/workflows/update-waproto.yml on the default branch.
  2. Go to Settings → Actions → General → Workflow permissions and select Read and write permissions. Without this the commit step fails.
  3. Open the Actions tab, select update-waproto, and press Run workflow (enable force for the first run).
  1. Taruh update.sh di root repo, dan file workflow di .github/workflows/update-waproto.yml pada branch default.
  2. Buka Settings → Actions → General → Workflow permissions, lalu pilih Read and write permissions. Tanpa ini langkah commit gagal.
  3. Buka tab Actions, pilih update-waproto, lalu klik Run workflow (aktifkan force untuk run pertama).

The zip is not committed to the repo. Download it from the Artifacts section of a finished workflow run. To build by hand:

OUT_DIR./

Where index.js, index.d.ts, WAProto.proto and the zip are written.

[04]NotesCatatan

  • The build uses ES module output (pbjs -w es6). Your Baileys version must use ES modules too, otherwise build with MODULE_FORMAT=commonjs.
  • Upstream changes can remove or rename message types. Review the diff before deploying to production.
  • To roll back WAProto, copy the *.bak files over their originals in node_modules/<package>/WAProto, or reinstall the package.
  • The workflow installs protobufjs and protobufjs-cli without pinning a version, so a new release can change the build output.
  • Piping a script from curl into node runs it with your permissions. Only use URLs from a repository you control or have reviewed. The short andhikagg.github.io URLs always serve the latest version. To avoid surprises from new commits, use https://raw.githubusercontent.com/andhikagg/waproto/<commit-hash>/fix.js instead (same for patch.js), and put the same hash in SOURCE.
  • GitHub may disable scheduled workflows after 60 days without repository activity. This workflow only commits when upstream changes, so do not rely on it to keep itself alive. If it gets disabled, re-enable it from the Actions tab.
  • Build memakai output ES module (pbjs -w es6). Versi Baileys yang kamu pakai juga harus ES module, kalau tidak, build dengan MODULE_FORMAT=commonjs.
  • Perubahan di upstream bisa menghapus atau mengganti nama tipe pesan. Cek dulu diff-nya sebelum dipakai di produksi.
  • Untuk rollback WAProto, salin file *.bak menimpa file aslinya di node_modules/<paket>/WAProto, atau pasang ulang paketnya.
  • Workflow memasang protobufjs dan protobufjs-cli tanpa mengunci versi, jadi rilis baru bisa mengubah hasil build.
  • Menjalankan skrip dari curl langsung ke node berarti skrip itu jalan dengan izinmu. Pakai hanya URL dari repo yang kamu kelola atau sudah kamu baca isinya. URL pendek andhikagg.github.io selalu menyajikan versi terbaru. Biar tidak kena dampak commit baru, pakai https://raw.githubusercontent.com/andhikagg/waproto/<hash-commit>/fix.js (begitu juga patch.js), dan isi SOURCE dengan hash yang sama.
  • GitHub bisa menonaktifkan workflow terjadwal setelah 60 hari tanpa aktivitas di repo. Workflow ini hanya commit saat upstream berubah, jadi jangan berharap ia menjaga dirinya tetap aktif. Kalau sampai nonaktif, nyalakan lagi dari tab Actions.

[05]TroubleshootingMasalah umum

TypeError: reader.size is not a function

The protobufjs runtime is older than the one the build was compiled for. Run fix.js to update it, then run patch.js again. This is not a session problem, so do not delete your auth/session folder.

Runtime protobufjs lebih lama daripada yang dipakai saat build dibuat. Jalankan fix.js untuk memperbaruinya, lalu jalankan patch.js lagi. Ini bukan masalah sesi, jadi jangan hapus folder auth/session.

Decode errors or protobufjs/minimal import errorsError decode atau error import protobufjs/minimal

Run fix.js, then check npm ls protobufjs for older nested copies.

Jalankan fix.js, lalu cek npm ls protobufjs kalau-kalau ada salinan bersarang yang lebih lama.

npm ls says invalid for protobufjsnpm ls menulis invalid untuk protobufjs

An older fix.js wrote "latest" into the package's package.json. Run the current fix.js again; it replaces it with a real version range.

fix.js versi lama menulis "latest" ke package.json paketnya. Jalankan fix.js yang sekarang lagi, ia menggantinya dengan rentang versi asli.

Import errors after patchingError import setelah patch

Module format mismatch. Rebuild with the matching MODULE_FORMAT.

Format modul tidak cocok. Build ulang dengan MODULE_FORMAT yang sesuai.

Type errors about proto or waprotoError tipe soal proto atau waproto

Run patch.js again; it renames waproto to proto in index.d.ts.

Jalankan patch.js lagi, skrip ini mengganti waproto jadi proto di index.d.ts.

"x" not found in …/node_modules or package "x" not found"x" not found in …/node_modules atau package "x" not found

Run the command from your project root and check the TARGET name.

Jalankan perintah dari root proyek dan cek lagi nama TARGET.

SOURCE must be https://

Use an https:// URL. http://localhost is only allowed for testing.

Pakai URL https://. http://localhost hanya boleh untuk pengujian.

Fix disappears after npm installPerbaikan hilang setelah npm install

node_modules was rebuilt. Run fix.js and patch.js again, or use the postinstall example above.

node_modules dibangun ulang. Jalankan fix.js dan patch.js lagi, atau pakai contoh postinstall di atas.

WhatsApp disconnects or errors after patchingWhatsApp terputus atau error setelah patch

If none of the entries above match, delete the auth/session folder and pair again.

Kalau tidak ada yang cocok di atas, hapus folder auth/session lalu pairing ulang.

Workflow does not appear in the Actions tabWorkflow tidak muncul di tab Actions

Check the path is exactly .github/workflows/update-waproto.yml, it is on the default branch, and the YAML indentation is valid.

Pastikan path-nya persis .github/workflows/update-waproto.yml, ada di branch default, dan indentasi YAML-nya benar.

git push is denied in the workflowgit push ditolak di workflow

Enable Read and write permissions (see the workflow setup above).

Aktifkan Read and write permissions (lihat bagian menyiapkan workflow di atas).

[06]Reporting problemsLapor masalah

If a build fails, the generated WAProto/ looks broken, or a script errors out and the entries above do not help, please open an issue. If a workflow build fails, WAProto/ keeps the last successful build and the workflow tries again on its next run, so your existing install is not affected.

Kalau build gagal, isi WAProto/ kelihatan rusak, atau skrip error dan daftar di atas tidak membantu, silakan buka issue. Kalau build di workflow gagal, WAProto/ tetap berisi hasil build terakhir yang sukses dan workflow akan mencoba lagi di run berikutnya, jadi instalasimu yang sudah ada tidak terpengaruh.

Please include:

Tolong sertakan:

  • the command you ran (with TARGET) and the full output
  • your Node.js version (node -v) and the output of npm ls protobufjs
  • your Baileys version, and whether it uses ESM or CommonJS
  • for a failed build: the link to the run in the Actions tab
  • perintah yang kamu jalankan (beserta TARGET) dan output lengkapnya
  • versi Node.js (node -v) dan hasil npm ls protobufjs
  • versi Baileys yang dipakai, dan apakah memakai ESM atau CommonJS
  • kalau build yang gagal: link run-nya di tab Actions

Do not paste auth/session files, tokens, or other secrets.

Jangan tempel file auth/session, token, atau rahasia lainnya.
